# 一、通用约定

## 1.1 环境与基础地址（Base URL）

| 环境 | Base URL | 说明 |
|---|---|---|
| 开发环境（DEV） | `https://dev-api.youxuan.com` | 开发联调，数据随时重置 |
| 测试环境（TEST） | `https://test-api.youxuan.com` | **测试主用环境**，数据相对稳定 |
| 预发环境（UAT） | `https://uat-api.youxuan.com` | 与生产同构，发布前验证 |
| 生产环境（PROD） | `https://api.youxuan.com` | 正式环境，禁止测试写入 |

- 所有接口路径均以 `/api/v1` 为前缀，下文不再重复书写 Base URL 与版本前缀，仅给出相对路径（如 `/auth/login`）。
- 必须使用 HTTPS，HTTP 请求将被拒绝（返回 403）。

## 1.2 鉴权方式

- 除注册、登录、验证码、商品分类/列表/详情、可领取优惠券等明确标注「免鉴权」的接口外，其余接口均需登录。
- 登录后在请求头携带 JWT：

```
Authorization: Bearer {accessToken}
Content-Type: application/json
```

- accessToken 有效期 **2 小时**；refreshToken 有效期 **14 天**。
- accessToken 过期后，使用刷新接口换取新令牌；refreshToken 过期或失效则需重新登录。
- 令牌在登出、修改密码后立即作废。

## 1.3 通用请求头

| Header | 必填 | 说明 |
|---|---|---|
| `Authorization` | 鉴权接口必填 | `Bearer {accessToken}` |
| `Content-Type` | POST/PUT 必填 | `application/json`；文件上传为 `multipart/form-data` |
| `Accept-Language` | 否 | 语言，默认 `zh-CN`，可选 `en-US` |
| `X-Client-Type` | 是 | 客户端类型：`ios` / `android` / `mp`（小程序）/ `web` |
| `X-Client-Version` | 是 | 客户端版本号，如 `3.2.1` |
| `X-Device-Id` | 否 | 设备唯一标识，用于风控与限流 |
| `Idempotency-Key` | 关键写接口必填 | 幂等键，UUID，详见 1.7 |

## 1.4 统一响应结构

所有接口（含成功与失败）均返回如下信封结构：

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "traceId": "a1b2c3d4e5f67890"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | integer | 业务状态码，`0` 表示成功，非 0 表示业务失败（见错误码表） |
| `message` | string | 提示信息，成功为 `success`，失败为可读原因（可直接展示给用户） |
| `data` | object / array / null | 业务数据，失败时通常为 `null` |
| `traceId` | string | 链路追踪 ID，提 bug 时必须提供，便于后端排查 |

> 注意：HTTP 状态码与业务 `code` 是两层。例如参数校验失败时 HTTP 状态码为 400，业务 `code` 为 40001。客户端应优先判断 HTTP 层，再判断业务 `code`。

### 分页响应结构（list 类接口）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [ ],
    "pagination": {
      "page": 1,
      "pageSize": 10,
      "total": 126,
      "totalPages": 13,
      "hasNext": true
    }
  },
  "traceId": "..."
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `data.list` | array | 当前页数据 |
| `data.pagination.page` | integer | 当前页码，从 1 开始 |
| `data.pagination.pageSize` | integer | 每页条数 |
| `data.pagination.total` | integer | 总记录数 |
| `data.pagination.totalPages` | integer | 总页数 |
| `data.pagination.hasNext` | boolean | 是否有下一页 |

## 1.5 分页与排序约定

- 分页参数统一为 `page`（页码，默认 1，最小 1）与 `pageSize`（每页条数，默认 10，最大 100）。
- 排序参数 `sort`，格式为 `字段,方向`，方向取 `asc` / `desc`；多个排序用分号分隔，如 `sort=sales,desc;price,asc`。

## 1.6 数据格式约定

| 类型 | 格式 / 说明 | 示例 |
|---|---|---|
| 时间 | 字符串，ISO 8601，统一为东八区，格式 `yyyy-MM-dd HH:mm:ss` | `2026-10-07 14:30:00` |
| 时间戳（毫秒） | long，13 位毫秒级 Unix 时间戳 | `1781245800000` |
| 日期 | `yyyy-MM-dd` | `2026-10-07` |
| 金额 | **integer，单位为「分」**，禁止使用浮点数，避免精度问题 | `9999` 表示 99.99 元 |
| 布尔 | `true` / `false` | `true` |
| 手机号 | 11 位大陆手机号，字符串 | `13800138000` |
| 空值 | 字段缺失或为 `null`，不返回空字符串占位 | `null` |

## 1.7 幂等约定

- 创建订单、发起支付、支付回调等关键写接口，必须通过请求头 `Idempotency-Key`（UUID v4）保证幂等。
- 服务端在 24 小时内缓存该键：相同键 + 相同参数直接返回首次结果；相同键 + 不同参数返回 `409` 冲突（错误码 40901）。
- 因网络超时重试时，必须复用同一个 `Idempotency-Key`，严禁重新生成。

## 1.8 限流约定

- 基于 `X-Device-Id` / 用户 ID 限流。默认单用户 60 次/分钟；登录、短信/验证码类接口为 1 次/分钟、10 次/天。
- 触发限流返回 HTTP `429`，响应头含 `Retry-After`（建议等待秒数），业务错误码 42901。

## 1.9 通用错误码

| HTTP | code | message | 含义 |
|---|---|---|---|
| 400 | 40000 | 参数错误 | 请求参数格式不合法 |
| 400 | 40001 | 参数校验失败 | 字段缺失、类型错误、超出约束 |
| 401 | 40100 | 未登录或登录已过期 | 缺少/无效 token |
| 401 | 40101 | token 已失效 | 登出、改密后旧 token |
| 403 | 40300 | 无权限访问 | 已登录但无资源权限 |
| 404 | 40400 | 资源不存在 | 路径或资源 ID 不存在 |
| 405 | 40500 | 请求方法不允许 | 用错 HTTP 方法 |
| 409 | 40900 | 资源冲突 | 状态冲突、重复操作 |
| 409 | 40901 | 幂等键冲突 | 同键不同参数 |
| 422 | 42200 | 业务处理失败 | 语法正确但无法处理 |
| 429 | 42901 | 请求过于频繁 | 触发限流 |
| 500 | 50000 | 服务器内部错误 | 服务端异常 |
| 503 | 50300 | 服务暂不可用 | 维护或下游故障 |

> 各模块还有专属业务错误码（如订单 50xxx、支付 60xxx），在对应接口处列出。

# 二、认证模块（Auth）

## 2.1 用户注册

- **接口说明**：使用手机号 + 密码 + 短信验证码注册新账号。
- **请求方法 / 路径**：`POST /auth/register`
- **是否鉴权**：否（免登录）

**请求体参数（Body）**

| 字段 | 类型 | 必填 | 约束 / 说明 | 示例 |
|---|---|---|---|---|
| `mobile` | string | 是 | 11 位大陆手机号，唯一 | `13800138000` |
| `password` | string | 是 | 8~20 位，须含字母和数字，传输建议 RSA 加密 | `Test1234` |
| `smsCode` | string | 是 | 6 位短信验证码，5 分钟有效 | `483920` |
| `inviteCode` | string | 否 | 邀请码，6~8 位 | `YX8866` |
| `agreeProtocol` | boolean | 是 | 是否同意用户协议，必须为 `true` | `true` |

**响应 `data` 字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `userId` | integer | 新用户 ID |
| `accessToken` | string | 访问令牌 |
| `refreshToken` | string | 刷新令牌 |
| `expiresIn` | integer | accessToken 有效期（秒），固定 7200 |

**请求示例**

```json
{
  "mobile": "13800138000",
  "password": "Test1234",
  "smsCode": "483920",
  "inviteCode": "YX8866",
  "agreeProtocol": true
}
```

**成功响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "userId": 100023,
    "accessToken": "eyJhbGciOiJIUzI1NiJ9.eyJ1aWQiOjEwMDAyM30.xxxx",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9.eyJ0eXBlIjoicmVmcmVzaCJ9.yyyy",
    "expiresIn": 7200
  },
  "traceId": "reg01a2b3"
}
```

**业务规则 / 边界**

1. 手机号已注册返回 `409 / 10001`「该手机号已注册」；
2. 短信验证码错误或过期返回 `400 / 10002`；验证码使用一次即失效；
3. `agreeProtocol` 为 `false` 返回 `400 / 10003`「请先同意用户协议」；
4. 密码强度不足返回 `400 / 10004`，并提示具体规则；
5. 同一手机号 1 分钟内仅允许请求注册相关接口 1 次；
6. 注册成功即视为登录，直接返回双令牌。

## 2.2 用户登录

- **接口说明**：手机号 + 密码登录，支持图形验证码（风控触发时必填）。
- **请求方法 / 路径**：`POST /auth/login`
- **是否鉴权**：否

**请求体参数**

| 字段 | 类型 | 必填 | 约束 / 说明 | 示例 |
|---|---|---|---|---|
| `mobile` | string | 是 | 11 位手机号 | `13800138000` |
| `password` | string | 是 | 密码 | `Test1234` |
| `captchaId` | string | 条件必填 | 图形验证码 ID，连续失败 2 次后必填 | `cap_9f8e7d` |
| `captchaCode` | string | 条件必填 | 图形验证码内容，4 位 | `aK7q` |

**响应 `data` 字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `userId` | integer | 用户 ID |
| `nickname` | string | 昵称 |
| `avatar` | string | 头像 URL |
| `accessToken` | string | 访问令牌 |
| `refreshToken` | string | 刷新令牌 |
| `expiresIn` | integer | 有效期（秒） |
| `isNewUser` | boolean | 是否新设备登录 |

**成功响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "userId": 100023,
    "nickname": "优选用户_8000",
    "avatar": "https://cdn.youxuan.com/avatar/default.png",
    "accessToken": "eyJhbGciOiJIUzI1NiJ9.access.zzzz",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9.refresh.wwww",
    "expiresIn": 7200,
    "isNewUser": false
  },
  "traceId": "login02b3c4"
}
```

**业务规则 / 边界**

1. 手机号未注册返回 `404 / 10005`「账号不存在」；
2. 密码错误返回 `400 / 10006`「手机号或密码错误」（出于安全，不明确指出是哪一项错误）；
3. 连续密码错误 2 次后，要求图形验证码；连续错误 5 次锁定账号 30 分钟，返回 `423 / 10007`；
4. 图形验证码错误返回 `400 / 10008`，并刷新验证码；
5. 账号被封禁返回 `403 / 10009`，message 说明封禁原因及时长；
6. 登录成功后旧的有效 accessToken 仍可用至自然过期（支持多端），但可通过服务端配置「单点登录」使其失效。

## 2.3 退出登录

- **接口说明**：登出当前设备，作废当前 accessToken 与 refreshToken。
- **请求方法 / 路径**：`POST /auth/logout`
- **是否鉴权**：是

**请求体参数**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 无 | — | — | 无需请求体，可传 `{}` |

**成功响应示例**

```json
{ "code": 0, "message": "success", "data": null, "traceId": "logout03c4d5" }
```

**业务规则 / 边界**

1. 登出后再使用原 token 返回 `401 / 40101`；
2. 仅作废当前设备令牌，不影响其他端；
3. 未携带 token 调用返回 `401 / 40100`。

---

## 2.4 刷新访问令牌

- **接口说明**：accessToken 过期时，用 refreshToken 换取新的双令牌。
- **请求方法 / 路径**：`POST /auth/refresh-token`
- **是否鉴权**：否（使用 refreshToken，不走 accessToken）

**请求体参数**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `refreshToken` | string | 是 | 登录/注册时获得的刷新令牌 | `eyJhbGci...wwww` |

**成功响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9.newaccess.aaaa",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9.newrefresh.bbbb",
    "expiresIn": 7200
  },
  "traceId": "refresh04d5e6"
}
```

**业务规则 / 边界**

1. refreshToken 无效、过期返回 `401 / 10010`「登录已过期，请重新登录」；
2. refreshToken 已被旋转（旧 refreshToken 重复使用）返回 `401 / 10011`，并触发风控、作废该用户全部令牌；
3. 刷新采用「旋转 + 有效期续期」机制：每次刷新同时下发新 refreshToken，旧的立即失效；
4. 已登出 / 已改密的 refreshToken 不可用。

## 2.5 获取图形验证码

- **接口说明**：获取图形验证码图片，用于登录、敏感操作的人机校验。
- **请求方法 / 路径**：`GET /auth/captcha`
- **是否鉴权**：否

**查询参数（Query）**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `scene` | string | 否 | 场景：`login`（默认）/ `sms` / `sensitive` | `login` |

**响应 `data` 字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `captchaId` | string | 验证码 ID，后续校验时回传 |
| `captchaImage` | string | Base64 编码的验证码图片（含 `data:image/png;base64,` 前缀） |
| `expireSeconds` | integer | 有效期（秒），固定 120 |

**成功响应示例（截断）**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "captchaId": "cap_9f8e7d6c5b4a",
    "captchaImage": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...（省略）",
    "expireSeconds": 120
  },
  "traceId": "captcha05e6f7"
}
```

**业务规则 / 边界**

1. 验证码 2 分钟有效，校验一次即失效，无论对错；
2. 同一 `captchaId` 不可重复使用；
3. 不区分大小写（字母验证码）；
4. 频繁请求（>20 次/分钟）触发限流 `42901`。

## 3.2 修改个人信息

- **接口说明**：修改昵称、性别、生日、邮箱等资料，支持局部更新（仅传需修改字段）。
- **请求方法 / 路径**：`PUT /users/me`
- **是否鉴权**：是

**请求体参数**

| 字段 | 类型 | 必填 | 约束 / 说明 | 示例 |
|---|---|---|---|---|
| `nickname` | string | 否 | 1~16 字符，不能含特殊符号，不能与他人重复（部分敏感词拦截） | `新昵称` |
| `gender` | integer | 否 | 仅允许 `0/1/2` | `2` |
| `birthday` | string | 否 | `yyyy-MM-dd`，不能晚于今天、不能早于 1900-01-01 | `2003-05-20` |
| `email` | string | 否 | 标准邮箱格式，需已完成邮箱验证（本版本可直接绑定） | `a@b.com` |

**成功响应**：返回更新后的完整资料，结构同 3.1。

**业务规则 / 边界**

1. 所有字段均为可选，但不能整体为空对象，否则返回 `400 / 40001`；
2. 昵称含敏感词返回 `422 / 20001`；昵称重复返回 `409 / 20002`；
3. 生日为未来日期返回 `400 / 20003`；
4. 邮箱格式错误返回 `400 / 20004`，邮箱已被绑定返回 `409 / 20005`；
5. 非法枚举值（如 gender=9）返回 `400 / 40001`。

## 6.2 添加商品到购物车

- **请求方法 / 路径**：`POST /cart/items`
- **是否鉴权**：是

**请求体参数**

|---|---|---|---|---|

| `quantity` | integer | 是 | 数量，1~99（单类） | `1` |
| `selected` | boolean | 否 | 是否默认勾选，默认 true | `true` |

**成功响应示例**

```json

}
```

**业务规则 / 边界**

1. SKU 不存在 / 已下架返回 `404 / 40002`；
2. 同一 SKU 已在购物车则数量累加，不新增行；
3. 加入数量或累加后数量超过库存返回 `422 / 40003`「库存不足，当前可购 N 件」；
4. 单次数量 <1 或 >99 返回 `400 / 40004`；
5. 购物车商品种类上限 50，超出返回 `422 / 40005`。

# 七、订单模块（Order）

## 7.1 订单状态机

| 状态码 | 状态名 | 说明 | 可执行动作 → 下一状态 |
|---|---|---|---|
| `10` | 待付款 | 下单成功，等待支付 | 支付成功 → `20`；超时(30 分钟)/用户取消 → `40` |
| `20` | 待发货 | 已支付，等待商家发货 | 商家发货 → `30`；申请退款 → `60` |
| `30` | 待收货 | 已发货，等待收货 | 确认收货/自动确认 → `50`；申请退款 → `60` |
| `40` | 已取消 | 订单取消，未支付直接关闭 | 终态 |
| `50` | 已完成 | 交易完成，可评价/售后 | 申请售后 → `60` |
| `60` | 退款/售后中 | 进入退款或售后流程 | 退款成功 → `70`；退款驳回 → 原状态 |
| `70` | 已退款 | 退款完成 | 终态 |

> 待付款订单 30 分钟未支付由系统自动取消并释放预占库存；待收货订单发货后 10 天自动确认收货。

## 7.3 创建订单

- **接口说明**：提交订单，预占库存、生成订单，返回订单号用于支付。
- **请求方法 / 路径**：`POST /orders`
- **是否鉴权**：是
- **幂等**：是，必须携带 `Idempotency-Key`

**请求体参数**

| 字段 | 类型 | 必填 | 约束 / 说明 | 示例 |
|---|---|---|---|---|
| `addressId` | integer | 是 | 收货地址 ID | `5001` |
| `itemIds` | string | 否 | 购物车项，逗号分隔；不传取全部已勾选 | `30001` |
| `couponId` | integer | 否 | 使用的优惠券 | `8001` |
| `payChannel` | string | 否 | 支付渠道预占：`alipay`/`wechat`，可在支付时再选 | `wechat` |
| `remark` | string | 否 | 订单备注，最长 50 | `尽快发货` |
| `source` | string | 否 | 来源：`cart`（默认）/ `buyNow` | `cart` |

**响应 `data` 字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `orderId` | integer | 主订单 ID |
| `orderNo` | string | 订单号（展示用） |
| `shopOrderNos` | array[string] | 拆单后的子订单号 |
| `status` | integer | 订单状态，固定 `10` 待付款 |
| `payAmount` | integer | 应付金额（分） |
| `expireSeconds` | integer | 支付剩余秒数，固定 1800 |

**成功响应示例**

```json
{
  "code": 0,
  "message": "下单成功",
  "data": {
    "orderId": 60001,
    "orderNo": "YX2026100714300001",
    "shopOrderNos": ["YX2026100714300001-1"],
    "status": 10,
    "payAmount": 214900,
    "expireSeconds": 1800
  },
  "traceId": "order22d3e4"
}
```

**业务规则 / 边界**

1. 未选择/无有效地址返回 `400 / 50001`「请选择收货地址」；
2. 购物车为空或无勾选商品返回 `400 / 50002`；
3. 库存不足返回 `409 / 50003`「商品库存不足」，并回滚预占；
4. 优惠券已使用/不满足门槛/失效返回 `422 / 50004`；
5. 重复提交（相同 Idempotency-Key）返回首次结果，不重复下单；缺幂等键返回 `400 / 50005`；
6. 下单成功后对应购物车商品被移除，库存预占 15 分钟；
7. 下单与支付非原子：下单失败不扣款；超时未支付自动取消。

## 8.3 支付结果回调（第三方 → 服务端）

- **接口说明**：支付渠道异步通知支付结果，服务端据此更新订单、扣减库存。
- **请求方法 / 路径**：`POST /payments/callback/{channel}`
- **是否鉴权**：否（由渠道签名校验，非用户登录）

**路径参数**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `channel` | string | 是 | `alipay` / `wechat` |

**请求体**：渠道原始报文（表单/JSON），含 `out_trade_no`、`transaction_id`、`total_amount`、签名等。

**成功响应**：按渠道要求返回纯文本，微信为 `SUCCESS`，支付宝为 `success`；否则渠道会重复通知（微信按 15s/15s/30s… 共 8 次）。

**业务规则 / 边界（重点）**

1. 必须先验签，伪造回调返回失败且记录风控，`401 / 60005`；
2. 必须幂等：以 `out_trade_no` + 渠道流水号去重，重复通知直接返回成功，不重复更新订单/扣库存；
3. 校验金额与订单应付一致，不一致不更新、告警，`409 / 60002`；
4. 仅当支付成功且订单为待付款时才流转状态、真实扣减库存、发通知；
5. 回调成功 ≠ 用户看到结果，前端仍需主动查询（8.2）。

## 8.4 申请退款

- **请求方法 / 路径**：`POST /orders/{orderId}/refund`
- **是否鉴权**：是
- **幂等**：是

**请求体参数**

| 字段 | 类型 | 必填 | 约束 / 说明 | 示例 |
|---|---|---|---|---|
| `refundReason` | string | 是 | 2~100 字符 | `商品与描述不符` |
| `refundAmount` | integer | 否 | 部分退款金额（分），不传为全额，不能超过实付 | `10000` |
| `evidenceImages` | array[string] | 否 | 凭证图片 URL，最多 6 张 | — |

**成功响应示例**

```json
{
  "code": 0,
  "message": "退款申请已提交",
  "data": { "refundNo": "RF2026100715000001", "status": 60 },
  "traceId": "pay29e0f1"
}
```

**业务规则 / 边界**

1. 仅 `待发货(20)/待收货(30)/已完成(50,售后有效期内)` 可申请，返回 `409 / 60006`；
2. 退款金额超实付返回 `400 / 60007`；
3. 已有进行中退款单返回 `409 / 60008`「退款正在处理中」；
4. 退款回调同样需验签 + 幂等；退款成功订单转 `已退款(70)`、库存回补。

| 60002 | 支付金额校验失败 |

## 9.3 领取优惠券

- **请求方法 / 路径**：`POST /coupons/{couponId}/receive`
- **是否鉴权**：是
- **幂等**：是

**成功响应示例**

```json
{
  "code": 0,
  "message": "领取成功",
  "data": { "userCouponId": 90001, "couponId": 8001, "validEndAt": "2026-10-31 23:59:59" },
  "traceId": "coupon31a2b3"
}
```

**业务规则 / 边界**

1. 券不存在 / 活动未开始或已结束返回 `404 / 70001`；
2. 已领完（receivedCount≥totalCount）返回 `409 / 70002`「优惠券已被抢光」；
3. 超过每人限领返回 `409 / 70003`；
4. 高并发领取需保证不超发（库存原子扣减），重复领取幂等。
